## Security review scope

Signup inserts only the account ID/display name and uses the Citizen role default. Profiles store the application role; user metadata does not grant privileges. Department assignments reference existing department names and require a non-null value for officers. Direct client table writes are denied. Guarded RPCs enforce administrator operations, department-scoped project changes, sequential complaint transitions, server-assigned report ownership and stale-write rejection. Citizens receive only their own private reports. Officers can read public projects and staff coordination across departments, but mutations remain department-scoped.

Local database tests exercise all three identities, unauthorized direct writes and RPC calls, own/other complaint visibility, missing/invalid departments, account escalation, project deletion constraints, timeline preservation, rollback and additive migration behavior. They execute PostgreSQL policy logic but do not establish that the hosted schema matches it.

Report photographs are restricted in the UI to JPEG/PNG/WebP at 1 MB and validated again as bounded image data URLs in the RPC. They remain in RLS-protected complaint rows; no public upload bucket is used. Auth restores verified sessions, hides configured-mode demo access and uses same-origin confirmation/recovery redirects. Hosted redirect allowlists and email delivery still require owner verification. This is a focused release audit, not a claim of an exhaustive penetration test.
